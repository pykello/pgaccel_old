aggregation, and result processing included. Warm statistics exclude
trial 1. Every trial must match the DuckDB typed answer. Raw files are
preserved beside this report under `pgaccel-star-vN-sf10.jsonl`.

The original PGAccel Q3 warm minimum was 8485.77 ms. Reference SF10
warm minima are 156.254 ms for DuckDB and 457.980 ms for ClickHouse.
The stricter fourfold threshold is therefore 39.064 ms. A promising
median alone does not establish the gate: fresh-process confirmation
and a subsequent SF100 comparison remain required.

CPU samples of v1 attributed 25.3% to bitmap selection, 22.5% to the
fact worker, 14.1% to selected-key decoding, and 10.3% to bridge work.
A separate instrumented v3 run measured roughly 7.5 ms for prefix and
payload initialization, 6.3 ms for release and aggregate initialization,
31–32 ms for fact scanning, and 4.8 ms for final candidates. Instrumented
runs are diagnostic evidence, excluded from the latency table.

All retained implementations are original and introduce no dependency.
See [ALGORITHMS.md](ALGORITHMS.md) for eligibility, exactness, and memory
accounting; [PLAN.md](PLAN.md) for primary research references.

This is a per-query optimization checkpoint. The complete-workload
baseline, including unsupported/capacity-limited cases, is unchanged.
