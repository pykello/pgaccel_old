# Current SF100 comparison: Q1, Q14, and Q3

All nine trials per query and engine validate. This is the final
three-query checkpoint, using the same frozen PGAccel binary as the
[fresh SF10 confirmation](SF10-CONFIRM.md). It does not replace the
complete 22-query SF100 baseline.

Eight workers, separate engine phases, 192 GiB service limits, and zero
swap. Client elapsed time includes execution, fetch, and answer conversion
for every engine. Warm statistics exclude only trial 1.

| Query | PGAccel median (ms) | DuckDB median (ms) | ClickHouse median (ms) | DuckDB / PGAccel | ClickHouse / PGAccel |
|---|---:|---:|---:|---:|---:|
| Q1 | 476.208 | 2353.558 | 6603.253 | 4.94× | 13.87× |
| Q14 | 136.472 | 1101.047 | 2219.293 | 8.07× | 16.26× |
| Q3 | 430.752 | 1934.584 | 3918.779 | 4.49× | 9.10× |

All three pass the fourfold warm-median target against both engines.
The earlier Q1-only binary was faster on Q1; its separate checkpoint
remains documented in [Q1-SF100.md](Q1-SF100.md). Use the table above
when comparing all three queries from one current binary.

| Query | PGAccel first trial (ms) | Warm min (ms) | Warm max (ms) | Query allocation peak (MiB) |
|---|---:|---:|---:|---:|
| Q1 | 495.269 | 471.272 | 516.242 | 1.01 |
| Q14 | 134.573 | 132.969 | 137.845 | 3.39 |
| Q3 | 458.406 | 428.041 | 432.536 | 476.22 |

Even the slowest measured warm PGAccel trial for each query is below
one quarter of the fastest warm trial of either competitor. This is
evidence from these trials, not a general worst-case guarantee.

PGAccel engine revision: `68b24ea`; frozen binary:
`tpch-work/checkpoints/q3-star-final-query-runner`. All directories,
bitmaps, expression programs, filtering, aggregation, and final results
are rebuilt within each statement. No prepared join or result cache is
used. Resident native loading is outside query time and recorded in the
raw metadata. The query allocation budget is 64 GiB.

DuckDB 1.4.3 uses its persistent SF100 database. ClickHouse 26.8.2.7 uses
the preserved `tpch_sf100_mergetree` database on isolated ports
18123/19000, with column statistics and merges stopped before timing.
Q14 uses the documented DOUBLE ratio adaptation; Q1 and Q3 use original
SQL. Native PGAccel columns, DuckDB storage, and compressed MergeTree
are different physical representations of the same generated tables.
