# Q12: grouped conditional bitmap joins scale validation

Q12 passes the fourfold warm-median target against both engines at SF10
and SF100. Every measured answer validates. Query times are client
elapsed milliseconds, including execution, fetch, and answer conversion.
Warm statistics exclude only trial 1. Eight workers per engine.

| Scale | PGAccel median (ms) | DuckDB median (ms) | ClickHouse median (ms) | DuckDB / PGAccel | ClickHouse / PGAccel |
|---|---:|---:|---:|---:|---:|
| SF10 | 33.918 | 147.215 | 397.452 | 4.34× | 11.72× |
| SF100 | 345.871 | 1439.386 | 3429.545 | 4.16× | 9.92× |

The PGAccel median is also below one quarter of each competitor's
fastest warm trial. This is a measured gate, not a worst-case guarantee.
SF10 uses 15 fresh PGAccel trials and the three-trial competitor baseline.
SF100 uses nine fresh trials for every engine, run in separate phases.

| Scale | PGAccel first trial (ms) | Warm min (ms) | Warm max (ms) | Query allocation peak (MiB) |
|---|---:|---:|---:|---:|
| SF10 | 47.983 | 33.451 | 43.683 | 22.11 |
| SF100 | 377.893 | 338.445 | 349.646 | 215.23 |

Engine checkpoint: `10b1a4e`. The same frozen PGAccel binary is used
at both scales; its SHA-256 and settings are preserved in the JSON report.
Original SQL is used. The statement rebuilds its temporary indexes and
includes filtering, date comparisons, grouping, and final ordering in
query time. No prepared result or join directory is cached.

SF100 services are capped at 192 GiB with swap disabled; PGAccel query
allocations are capped at 64 GiB. Loading resident native columns is
measured separately. DuckDB uses its persistent database and ClickHouse
uses the preserved MergeTree database with column statistics. Physical
representations differ; these are engineering comparisons of the same
generated tables, not audited TPC benchmark results.
